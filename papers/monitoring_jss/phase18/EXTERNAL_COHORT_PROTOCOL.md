# Prospective external-cohort screening protocol (29 October 2026)

**Status: design/screening only. No new case has been admitted or scored.** This protocol follows exposed Li.Fi and Revest results; those cases remain retrospective diagnostic cases for the revised historical-state evaluation.

## Independent admission sequence

1. Fix the candidate catalogue SHA and retain every screened entry, even when metadata/core/chain or archive data cannot be completed.
2. For the first wave require Ethereum mainnet, an independently verified *successful exploit-execution* transaction hash (not a preparation/recovery/sale), a fixed 30-day UTC observation window, and an independently justified contract-core nomination.
3. Disclose any incident-informed nomination; do not add attacker or downstream token addresses just to turn a known attack into a selected transaction.
4. Before scoring, verify complete enumerated source partitions, all core-emitter rows, each selected transaction's all-emitter log bundle and execution metadata. Missing evidence means unavailable, not zero.
5. Freeze the exact observation/feature rule, historical initialization, grouping, daily policies, reference-inventory conventions, and all SHA-256 inputs *before* new case scores.
6. Report label-free eligibility for the selected population, followed by exact notified verified references and realized alerts. Unknown notifications are not assumed false.
7. Count independent **incident families**, not methods, transactions, token scores or policy cells, as distinct research cases.
8. Report complete exclusions and missing evidence to prevent selection by successful detection outcomes.
