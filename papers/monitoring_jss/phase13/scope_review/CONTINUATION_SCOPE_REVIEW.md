## Proportional continuation

Historical code may be obtained for each facet at the checkpoint where it was observed. This answers whether the nominated dispatch destination has returned runtime bytes at that block and allows exact byte/hash comparison with already bound code. New code at a sampled address is not a source/runtime binding by itself; source semantics and continuous code identity remain separate claims. Delegatecall destinations do not automatically become monitored log emitters.

A new, prospectively frozen request schedule may change the transport chunk size while preserving the earlier refusal and accounting. This is an explicit acquisition amendment prompted by a known availability failure, not a successful rerun of the old frozen attempt. All ranges, topics, endpoint, order, caps and failure behavior must be fixed before new responses. No adaptive range splitting, silent retry, omitted failed request or provider substitution is acceptable within that attempt.

For the study-window claim, the independently checked pre-window checkpoint at block 14,233,162 is a justified observed initial state. Nominal replay from block 14,233,163 through 14,426,367 can therefore compare observed administrative history with the retained end checkpoint without reconstructing every earlier mutation from creation. Creation-to-end collection may provide separate bootstrap evidence, but is not a universal prerequisite for this interval-relative comparison. A block-end seed excludes the seed block itself; including its events again would double-apply earlier transitions.

Complete returned chunks and canonical ABI decoding support a statement about the provider-returned event list. Replay must preserve chain order, all distinct log identities, ordered cuts within one event and the source's swap-and-pop positions. A failure or discrepancy is a result to retain. It must not silently reset the initial state, discard a cut, modify targets or trigger outcome-dependent acquisition.

## Limits of a successful comparison

Even exact agreement between nominal replay and the final checkpoint does not prove that the provider returned every historical event, that no hidden intermediate states existed, or that all reachable writers were covered. The known DiamondCut source emits its event before an optional delegatecall initializer. An initializer can therefore matter even when the emitted cuts replay cleanly. Shared Inited-shaped events cannot be attributed to a unique facet or an effective bridge configuration solely from that signature. Relevant mutation paths require evidence proportional to the eventual routing claim; unused helpers and unrelated source universes are not automatic requirements.

Historical RPC results remain observations at the retained provider-evidence tier unless independently authenticated. A numeric block tag plus retained reference header is not a cryptographic state-root verification. Runtime bytes, observed event identities and snapshot comparisons should retain distinct provenance and not be promoted to source equivalence, activation epochs or complete protocol coverage.

No candidate order, study window, eligibility criteria, methods, thresholds, warmup, grouping or notification budgets change. No label joining, independent incident admission or Li.Fi detector scoring is authorized by this review. A fixed-address estimand amendment remains a separate, unadopted design choice. Missing core flow, cold start, an empty event result or weak detector response cannot justify exclusion or adding victim addresses to the monitored core. Previous scientific findings, failures and original source attachments remain unchanged.

The useful next result is a bounded account of sampled destination-code identity and the degree of agreement between returned administrative history and observed endpoint state. It can identify a small set of relevant initializer or writer targets for further work. It is not a new anomaly-detection algorithm or an independent performance experiment.
