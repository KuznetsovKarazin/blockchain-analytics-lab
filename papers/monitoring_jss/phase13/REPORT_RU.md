# Статья 2: этап 13 — код компонентов Li.Fi

26 октября 2026. **Получены пять новых точных привязок исторического байткода к исходникам. Для всех 14 общих селекторов, у которых между границами окна изменился адрес компонента, различается и полный байткод назначения.** Полная история маршрутизации пока не восстановлена; оценки детектора Li.Fi не вычислялись.

Проверены 19 пар «адрес компонента — снимок» для 14 адресов. Сделано 18 новых запросов кода, ещё один точный ответ использован из предыдущего этапа. Во всех наблюдениях код непустой. У четырёх компонентов, присутствующих на обеих границах окна, байткод в этих двух снимках совпадает.

Сохранённый и ранее независимо воспроизведённый результат компиляции позволил провести 684 точных побайтных сравнения без новых компиляций и загрузки исходников. Совпали 11 наблюдений для шести компонентов:

| Компонент | Снимки с точным совпадением |
|---|---|
| DiamondCutFacet | Создание, начало, конец |
| DiamondLoupeFacet | Начало, конец |
| OwnershipFacet | Начало, конец |
| WithdrawFacet | Начало, конец |
| NXTPFacet | Начало |
| CBridgeFacet | Начало |

CBridge был связан с исходниками раньше; остальные пять привязок новые. Это позволяет проверять соответствующие административные функции по точным исходникам. Для восьми других адресов совпадений в имеющемся результате компиляции нет. Это не свидетельство вредоносности или отсутствия исходников.

Исторические события получить не удалось. Первый запрос диапазона из 5 000 блоков был отклонён dRPC. Отдельно зафиксированная попытка через PublicNode остановилась ещё на обязательном заголовке начального блока: провайдер сообщил о недоступной старой истории. Контрольный запрос известных событий и запросы рабочего окна после этого не выполнялись. Оба отказа сохранены; они не означают отсутствия событий.

Итого за этап: **21 новый RPC-запрос, 154 743 байта ответов, ноль успешных диапазонов событий**. Независимая проверка фактических запросов, сопоставления кода и учёта затрат отражена в [отчёте проверки](qa/QA_PUBLIC.md). Старые тестовые наборы не запускались повторно.

Для статьи это полезный результат о корректности измерений: неизменный хеш кода входного контракта не определяет адреса и байткод выбранных им компонентов. При этом различие полного байткода, включая метаданные, само по себе не доказывает различия поведения. Снимки также не устанавливают моменты изменений и непрерывность состояния. Научный вклад этого этапа связан с воспроизводимостью и обоснованием границ наблюдения; улучшение качества обнаружения атак пока не измерено.

Принятые окно `[2022-02-19, 2022-03-21)` UTC, порядок кандидатов и методы сохранены. Новых допущенных случаев нет. Следующий шаг должен опираться на подтверждённую доступность нужной исторической информации либо на отдельное перспективное изменение цели измерения для всей выборки. Простое повторное уменьшение диапазонов без новых оснований не продвинет исследование.
