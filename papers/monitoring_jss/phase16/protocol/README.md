# Two-case measurement and post-decision reference protocol

The two configs retain the exact frozen method parameters and independent UTC-day resets. LiFi uses its historical diamond over February19–March20,2022; Revest uses its controller and legacy TokenVault over February26–March27. Each window has30 complete days and810 day/method/policy/budget cells. The two incidents are the scientific units;1620 cells are not1620 independent replications.

The primary comparison is outflow rank1/20 versus the transaction-final count rule at daily cap5. Report all three fixed admission policies. Rank1/10 and caps1/20 are descriptive sensitivities. Equal offered budgets need not yield equal actual load; report both. No threshold, core, history or policy is chosen after results.

`measurement_protocol.json` declares the source, replay and reporting sequence. `core_nominations.json` preserves the accepted finite sets and exposure. `denominators.json` retains the entire frame, all verified reference executions, unavailable evidence and incident-level uncertainty. `label_join_protocol.json` freezes a bounded post-decision primary-reference procedure without acquiring any positive hash here.

Both decision sets must be closed and sealed before new reference retrieval. The reference reviewer starts from the same named primary reports for each case, records every reported transaction candidate and role, and checks actual identity/status without consulting detector scores. Reuse the retained archive evidence first; the fixed Blockscout V2 fallback is bounded and retains its indexer evidence tier. A completed report search, one named transaction or agreement between reports does not prove a complete incident inventory.

Join only exact `(chain_id,transaction_hash)` identities. A notification on a neighboring transaction, in the same block, or on the group's anchor does not give execution credit. A known execution with a fully checked no-core-log result remains an observed selection miss and is not inserted into detector inputs. Missing source evidence remains unavailable. No hit in an incomplete positive inventory means only known-subset noncoverage; a complete incident miss requires positively established inventory closure and complete observation evidence.

The union source window contains111 regular table objects. The February18 and March28 block partitions are two exterior controls, bringing the planned source-object count to113. They support surrounding UTC header checks and never extend the detector windows. Independently retained endpoint anchors must be identified as such; partition continuity is not receipt-root or full-chain authentication.

Root can use `prepare_measurement_acceptance.py` once the final source plan and execution files pass review. It copies the six gate files into a fresh per-case directory, binds the source plan and specified execution files, and emits the exact Phase15 driver acceptance schema. Use the explicit `--confirm-before-payload` assertion only before both new collection and restoration/reuse of raw tables for these case workloads. The helper records root's decision; it does not adjudicate source completeness, review the collector, or prove that the assertion is historically true. An existing output directory is never overwritten.

The helper requires `--case lifi|revest`, `--source-plan`, one or more `--execution-source` paths and `--output`. Root must enumerate every final collector/pipeline/source-auditor execution file and dependency receipt in the source plan or bindings; merely naming one file is not a complete freeze. Successful source audit and complete input validation remain required before replay. Unknown notifications are not false positives, and block timestamps support only logical replay, not measured live response or prevention.
